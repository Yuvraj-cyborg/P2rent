**mux 0.3.0 is the first release under the mux name.** It brings local copies,
HTTP downloads and transfers between machines into one CLI. You can now
share a folder with a ticket and sync that snapshot into a folder you already have.

## Install

Choose the standalone executable for your system. The archives also include the
README and license. [SHA-256 checksums](https://github.com/yuvichh/mux/releases/download/v0.3.0/checksums-sha256.txt)

| Platform | Executable |
| --- | --- |
| macOS | [Apple silicon](https://github.com/yuvichh/mux/releases/download/v0.3.0/mux-Darwin-arm64) · [Intel](https://github.com/yuvichh/mux/releases/download/v0.3.0/mux-Darwin-x86_64) |
| Linux (glibc 2.17+) | [x86-64](https://github.com/yuvichh/mux/releases/download/v0.3.0/mux-Linux-x86_64) · [ARM64](https://github.com/yuvichh/mux/releases/download/v0.3.0/mux-Linux-aarch64) |
| Windows | [x64 executable](https://github.com/yuvichh/mux/releases/download/v0.3.0/mux.exe) |

On macOS or Linux, run the following in the directory where you downloaded
the executable. Add `$HOME/.local/bin` to your `PATH` if needed.

```sh
mkdir -p "$HOME/.local/bin"
install -m 755 "mux-$(uname -s)-$(uname -m)" "$HOME/.local/bin/mux"
```

On Windows, open PowerShell in the download folder and run `.\mux.exe --version`.
To build from source with Rust 1.91 or later, run
`cargo install --git https://github.com/yuvichh/mux --tag v0.3.0 --locked cli`.

## What changed

- **Share across networks.** `mux cp ./photos peer:` prints a ticket. Keep
  the sender running and use `mux cp 'TICKET' ./downloads/` on the receiver.
  Iroh connects peers directly where possible and falls back to encrypted
  transfers through a relay. Every peer chunk is checked against the ticket's
  manifest.
- **Update a folder in place.** `mux sync 'TICKET' ./backup/photos --dry-run`
  previews the changes. Remove `--dry-run` to apply them. Extra files are
  kept by default. With `--delete`, paths present only at the destination go
  to trash alongside replaced files. Removing more than half of the destination's
  entries requires `--force`.
- **Reuse data already on disk.** Ticket transfers can recover verified
  chunks even after an insertion shifts the rest of a file. In a direct
  Mac-to-Linux sync, inserting 4 KiB into a 24 MiB file reused 23 MiB and
  fetched 1 MiB plus 4 KiB. A retry also reuses verified chunks from an
  interrupted transfer. Each file takes its final name when complete.
- **Download from the web.** `mux cp URL ./downloads/` supports HTTP range
  requests, resumable downloads on compatible servers and expected checksums
  with `--hash`. Add `--seed` to offer the result to other machines. A receiver
  can then fetch from the web origin and peers in the same transfer.
- **Use mux in a script.** `mux probe` inspects a source, `--json` emits
  structured output and exit codes distinguish usage, reachability, changes
  at the source and verification failures.

## Upgrading from p2rent 0.2

Upgrade both ends of a transfer. The peer protocol changed with iroh, so
0.2 peers and tickets are incompatible with 0.3. Re-offer existing files to
get new `mux://` tickets. The command is now `mux`, and the key override is
`MUX_KEY`. On first use of the default key location, mux adopts the previous
p2rent device key. The `seed` and `get` commands remain available.

A ticket pins one snapshot. Offer the updated folder and sync the new ticket
to pick up subsequent edits.
