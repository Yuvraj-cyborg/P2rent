Copy and sync files between machines.

One command sends a folder to any other machine, through home routers, with every byte checked. mux also downloads from the web and keeps a folder in step with its source. It is free, open source, and runs on Linux, macOS and Windows.

Install on macOS or Linux

$ curl -fsSL https://raw.githubusercontent.com/yuvichh/mux/main/install.sh | sh

Or brew install yuvichh/tap/mux. There are also builds for Windows, Nix and by hand.

What it does

Three jobs, one command. The output below is from real runs.

Send a folder

Run one command where the files are. It prints a ticket. Run one command with that ticket where the files should go.

There is no account and no port to open, and it works when both machines sit behind home routers. A copy that is cut off carries on when you run the command again.

# on the machine that has the files
$ mux cp ./photos peer:
seeding  photos  (23.17 MiB, 28 chunks)
mux://c11f…

# on the other machine, with the ticket it printed
$ mux cp 'mux://c11f…' ./downloads/
saved    ./downloads/photos  (23.17 MiB, verified)

Sync a folder

mux sync makes a folder match its source and fetches only what changed. Here a photo was added and 4 KB were put into the middle of a 9 MB video: of 10.59 MiB that changed, it fetched 3.59 and reused the rest.

Preview with --dry-run. Nothing is removed without --delete, and what is replaced or removed goes to a trash folder first.

$ mux sync 'mux://8a41…' ./backup/photos --delete --dry-run
touch	.
touch	2026
add	2026/IMG_107.jpg
remove	notes.txt
replace	trip.mov
would add 1, replace 1, touch 2 and remove 1, and kept 6  (10.59 MiB to bring)

$ mux sync 'mux://8a41…' ./backup/photos --delete
added 1, replaced 1, touched 2 and removed 1, and kept 6  (3.59 MiB fetched, 7.00 MiB reused)
what was replaced or removed is in ./backup/photos/.mux-trash/1795289743.047642000

Download from the web

Give it a web address. It fetches a file in several parts at once and carries on after a break.

With --hash it checks the file against a digest you give. With --seed it goes on to offer the file to your other machines, which then fetch from the web and from each other at once.

$ mux cp https://github.com/yuvichh/mux/releases/download/v0.3.0/mux-x86_64-linux.tar.gz ./downloads/
saved    ./downloads/mux-x86_64-linux.tar.gz  (5.86 MiB, consistent)

Made for scripts and agents too

Every command takes --json and writes one JSON object on each line. The exit code says whether running the command again is worth it.

0
Done
2
The command is written wrong
3
Nothing is at the source
4
Unreachable: run it again
5
The source changed: run it again
6
What arrived is not what was asked for

An agent can read how to use mux in one fetch: llms.txt.

$ mux --json cp https://github.com/yuvichh/mux/releases/download/v0.3.0/checksums-sha256.txt ./downloads/
